## 1. 本次交付

原仓库的单文件 Python 程序只能读取预录视频中的单个心率 ROI。本分支新增浏览器 Web 原型，形成三条明确的 HR 流程和一条独立的手工用药记录流程：

- 在线：摄像头 → HR ROI → 本地 OCR → 固定五分钟时间槽 → 简体中文复诵 → 人工核对 → CSV/JSON；
- 离线：本地 MP4/MOV → 媒体时间抽帧 → 标准模式每槽五帧 HR 共识，或 1 秒模式每槽三帧 HR 共识 → HR 解析/拒识规则 → 草稿表 → 人工核对 → CSV/JSON；
- 对比：本地 HR 参考 CSV → `video_time_s` 对齐 → 派生/人工修订排除 → exact/±2/±5、MAE、RMSE、Bias、拒识和逐点差异 → 独立对比 CSV/JSON。
- 用药记录：医院自定义药物目录 → 一次事件选择多种药 → 手工填写阶段、时间、各药剂量文本/单位/途径/备注 → 编辑/删除与审计 → 用药 CSV、审计 CSV、JSON。

**当前产品和本次验收只覆盖 HR。** SpO₂、PR、NIBP、RR、EtCO₂、FiCO₂、TEMP 全部后置；仓库内遗留的这些字段 ROI、解析、数据模型和测试属于实验/历史兼容代码，不进入当前 HR 分析、记录、播报、导出或参考对比流程，也不构成“已支持”的证据。HR 低置信、横线、遮挡、范围错误或多帧冲突会保持缺失/待核对，不会沿用上一行数值。播报固定使用 `zh-CN` 简体中文，必须先由用户点击测试并收到成功事件；离线批处理仅在全部完成后播报一次，避免逐行重复播报。

当前 HR 后处理要求 **唯一整数且位于 0–200 bpm（含端点）**。该范围只用于 OCR 工程捕获，不代表动物心率的临床正常范围或报警线。单字符 `0–9` 保留为待核对候选，不能因多帧重复自动升级；多候选、小数、负数和超范围结果拒识。系统严禁将越界值钳制到边界、按上一读数补齐缺失位或前向填充。

跨槽自动接受门以最后一条已接受 HR 为基准，允许差值为 `max(8 bpm, 该 HR 的 15%)`。第一个越门候选只作为待核对的大跳候选；仅当下一连续槽候选与其相差不超过 `±2 bpm` 时，才接受第二槽自身的候选。两次候选不取平均，首个待核对槽不追溯补写，缺失槽不前向填充；这是一条 OCR 稳定规则，不是临床报警规则。

联合用药模块只记录人工输入事实：药物目录初始为空且由医院自定义，一次事件可含多种药。系统不预置默认药物或剂量，不自动解析/计算剂量，也不提供药物、配伍、禁忌或临床建议。

视频、摄像头画面和裁剪图不进入仓库，也不会由应用主动上传。浏览器只持久化病例草稿、HR 数值/状态/审计，以及手工用药事件、医院目录与相关审计记录。

## 4. 跨平台收口

- Windows/macOS 使用同一份前台 HTTPS Web/PWA；Android 10+ 当前版 Chrome 与 iOS/iPadOS 17+ Safari 目前仅为前台条件支持目标，真机尚未验收，平台状态条使用能力检测而不是仅靠 UA 猜测；
- 摄像头按“指定设备 → 后置镜头偏好 → 任意镜头”降级，权限被拒绝时不重复弹框；
- 已补 PWA manifest、Apple 主屏幕图标、safe-area、`100dvh`、44 px 触控目标、横竖屏比例更新、Wake Lock 及移动分享降级；
- 语音仅选择简体中文普通话音色，必须先由用户测试成功才启用自动播报；错误或超时会关闭自动播报并给出可见提示；
- 草稿存储升级为 v2，可迁移旧 v1 记录；配额/私密模式导致保存失败时会持续警告立即导出；
- 离线抽帧必须等待 rVFC 回调的 `metadata.mediaTime` 匹配目标时间；不安全的 `requestAnimationFrame`/定时回退已移除，不支持或超时会明确失败且不写伪记录；
- 1 秒 HR 模式在各端共用浏览器实现，但完成时间是设备级指标；手机可能因省电、散热和内存限制更慢或中止，不保证手机端吞吐、完成时间或一定完成，所以长视频优先在接电的 Windows/macOS 前台浏览器验收；
- GitHub Actions 工作流已在本地配置 Ubuntu、Windows、macOS 三系统逻辑测试矩阵，但当前改动尚未 commit/push，工作流和 Pages 均未运行或部署。移动端的真实镜头、视频抽帧、系统声音和分享面板仍必须用 Android/iOS 真机验收。

后台或锁屏持续摄像头 OCR 明确不在支持范围内；当前实现的安全语义是暂停、记缺失、回到前台后人工恢复，不是在后台冒充实时记录。详见 [`CROSS_PLATFORM_COMPATIBILITY.md`](CROSS_PLATFORM_COMPATIBILITY.md)。

## 6. 用户验收步骤

1. 先确认交付前最终全量自动化测试通过，记录测试命令与实际输出，不在文档中预设固定用例总数。重点确认 0/200 含端点、非法候选拒识、单字符待核对，以及不钳制、不猜值、不前向填充。
2. 用确定序列验证跨槽门：例如已接受 100 后出现 130，首个 130 必须待核对；下一连续槽为 128–132 时，只接受第二槽自身值。首槽仍待核对，结果不取平均、不追溯补写。
3. 打开本地页面，点击“导入视频”，选择 `1.mp4`。
4. 确认页面显示 `10:02`、`544 × 960`、`88.0 MB` 和“已应用独立 ROI 布局”；暂停在清晰画面检查 HR 框。
5. 在“HR 参考结果对比”中导入 `8.8_143312_hr_data_full.csv`，确认显示 603/481/122 和末尾差 0.333 s。
6. 保持 offset `0`、容差 `0.5`；先选择“5 分钟（标准）”并确认生成 `00:00`、`05:00`、`10:00` 三行且对齐 3/3。
7. 检查每个抽取帧都来自 rVFC 回调且 `metadata.mediaTime` 匹配目标；模拟超时/不支持时应停止并提示，不得以动画帧或定时器回退生成记录。
8. 逐帧复核所有三点并记录当前版本结果；不得直接抄用旧版本的 46/46、52/52、末点 25 或 2/3 覆盖数字。
9. 点击“导出对比 CSV”和“JSON 审计”，确认包含来源文件、参考行号、原始/过滤值、对齐误差、OCR 状态、差值、来源质量和主指标纳入状态。
10. 所有黄色“待核对”项均对照原视频逐格修订并填写原因，再勾选“已核对”；人工修订不应反向改变算法主指标。
11. 需要更多抽样时可先改为 1 分钟（11 点）或 30 秒（21 点）；稀疏抽样不能外推为 603 行逐秒准确率。
