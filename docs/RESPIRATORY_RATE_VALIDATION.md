# HR + RR 采集验证（2026-09-15）

## 本次变更

- 激活 RR 呼吸率，保留六项其他参数为未启用；心率参考 CSV 对比仍只针对 HR。
- 两个独立 ROI、实时数值/趋势、录入状态、人工修订、播报和记录列。
- 实时在同一冻结画面中串行识别 HR 与 RR，全部完成后一次更新；单项 OCR 异常不会跳过另一项。每项要求连续两次一致，切换后台或停止会清空连续候选。
- 标准离线每项每槽五帧，逐秒每项每槽三帧；RR 使用严格多数，数字截断冲突不猜长值或短值。
- RR 工程捕获范围 0–180 次/分钟的唯一整数，包括 0 和个位数；拒绝小数、负数、多数字、前导零、字母替代。不是临床正常范围。
- CSV 包含 RR、候选值、置信度、状态、原文及 RR 采集 UTC 时间，与 HR 共用时间槽。未知视频起点时两项绝对时间均留空。已有 HR 记录的 RR 不回填。
- 自动保存文件名更新为 `病例_HR_RR_会话ID_最新完整记录.csv`；CSV 全量覆盖写入，JSON 审计结构为 `petor-monitor/vital-record-export/2.0`。

## 验证与边界

本地 25 个测试文件、204 项测试通过。覆盖 RR 解析边界、多帧共识、实时两次确认、与 HR 同步的离线输出、缺失值、人工修订及审计、草稿迁移、CSV/JSON 导出和五分钟保存含边界行。原 HR 跳变确认、失败中断、用药记录和参考对比回归通过。

在本地真实浏览器检查了 RR 框选按钮、双指标卡片、演示数据与记录表：一次手动记录生成 HR=116、RR=17 的同一行，状态完整。这是模拟输入的 UI 检查，不是实拍 OCR 准确率测试。

现有历史视频 fixture 中的 RR `3/13` 数字截断冲突现在拒绝自动选择，保留待核对。没有用本次新增 RR 模块完成真实设备长视频的逐帧人工对照验收，也没有完成真实摄像头 24 小时耐久试验。文件写入测试使用 mock；实际文件夹授权及磁盘落盘仍需在目标 Chrome 中检查。
